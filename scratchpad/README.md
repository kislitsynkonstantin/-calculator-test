# scratchpad

Рабочие списки, из которых собираются справка и указатель макетов. Здесь лежит
то, что нужно правке в двух местах сразу — чтобы места не разъезжались.

- `макеты.py` — единый список всех макетов: файл, дата, название, строка о чём.
  Из него собран раздел «Макеты» в главе «Лог развития» справки и список
  в `mockups/index.html`. Появился новый макет — дописывать сюда, а не
  в два места руками.
- `справка.py` — сборка справки и руководства из частей. Текст лежит не
  здесь: этот репозиторий публичный, и справка уехала из него в таблицу
  `app_docs` (19.09.2026). Источник — закрытый репозиторий рабочей области,
  `docs/справка/`; путь переопределяется переменной `BM_MANUAL_SRC`.

Проба `check_manual_ext_links.py` сверяет справку с папкой `mockups/`: каждая
ссылка обязана открываться, каждый файл — быть упомянутым.

## probes/

Пробы и заглушка к ним. Лежат в репозитории нарочно: контейнер пересоздаётся,
и написанные «на один раз» пробы пропадают вместе с ним — так было дважды,
а CHANGELOG при этом ссылался на файлы, которых в репозитории нет.

- `stub_sb.js` — заглушка Supabase: домен базы закрыт шлюзом наружу, а разметке
  и расстояниям настоящие данные не нужны. Подменяет `supabase.createClient`
  до первого скрипта страницы.
- `check_link_head.py` — панель печати: строка «Ссылка клиенту», кнопка
  копирования, разворот птичкой, «Печать / PDF», окно уведомлений. Четыре окна,
  включая телефон лёжа. Снимки кладёт рядом.
- `check_client_visit_count.py` — что отправляет клиентская страница при
  приходе, обновлении, возврате во вкладку и предпросмотре.
- `check_client_sheet.py` — клиентский лист: ни плашки о сроке цены, ни строки
  версии; лист кончается оговоркой, дата срока остаётся в итоге и в полоске.
- `check_manual_updates.py` — справка: ссылки журнала, длина абзацев, доля
  ссылок к пунктам, «менеджер» в третьем лице, эмодзи; снимки правленых глав.
- `check_notify_presets.py` — уведомления и коды пресетов: администратор видит
  заходы по ссылкам всех менеджеров с подписью менеджера и открывает их снимком
  из ссылки, менеджер — только свои; кнопки «Поделиться» нет, код есть у каждой
  карточки, уникальность кода спрашивается у функции базы.
- `check_blank_windows.py` — тема «Бланк» и замок: кнопки над списком опций не
  наезжают на вкладки и не касаются линейки ряда (обе темы, три ширины), замок
  комплектаций переключается сразу и возвращается при отказе базы, шапка окна
  «Данные для договора» светлая, раздел таблицы держится чертой.
- `check_kits_copy.py` — комплектации: полоса добора из нижнего уровня (только
  добавляет, источник и снятые базовые не трогает), разбор в диалоге
  копирования, метка «проверить цену» на ручных из чужого проекта, замок,
  и сборка всех четырёх уровней по образцу другого проекта — с расхождениями
  по кровле и этажности и открытым замком после неё.
  Корень подменяется переменной `BM_ROOT` — так проба проверяется прогоном по
  прежней версии файла.
- `check_manual_from_db.py` — справка приходит из базы: спрошена до нажатия,
  у менеджера без внутренней главы и без пункта меню на неё, второе открытие
  без запроса, молчание базы объяснено словами, а не пустым окном.

Снимки (`*.png`) — рабочие, в git не идут.

Путь к браузеру пробы берут из `BM_CHROMIUM` — переменную кладёт хук запуска
сессии `.claude/hooks/session-start.sh`. Нет переменной — ищут сами по
`/opt/pw-browsers/chromium-*`: номер сборки в пути меняется вместе с образом,
и вписанный в пробу он однажды перестал бы совпадать.

`check_canvas_resize.py` — уголок размера у снимков: тянется пальцем и мышью,
жест не уходит браузеру, поле нажатия 44 px, крестик рядом цел. Два окна:
в облике телефона Chromium шлёт только касания, и мышь там не проверить.
